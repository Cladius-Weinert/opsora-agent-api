// quick start

Get started in 3 steps. You'll be making API calls in under 2 minutes.

1

Get your API key

Sign up at opsora.ai/dashboard and generate an API key. Keys start with opsora-sk- and are shown once — save it somewhere safe.

2

Install the OpenAI SDK

Opsora is fully OpenAI-compatible. Use the SDK you already know.

install 
# Python
pip install openai

# Node.js
npm install openai
3

Make your first request

Pick your language below and copy the example.

from openai import OpenAI

client = OpenAI(
    base_url="https://api.opsora.ai/v1",
    api_key="opsora-sk-xxxxx",
)

response = client.chat.completions.create(
    model="opsora-fast",
    messages=[
        {"role": "user", "content": "Explain quantum entanglement in one sentence."}
    ],
)

print(response.choices[0].message.content)
import OpenAI from "openai";

const client = new OpenAI({
  baseURL: "https://api.opsora.ai/v1",
  apiKey: "opsora-sk-xxxxx",
});

const response = await client.chat.completions.create({
  model: "opsora-fast",
  messages: [
    { role: "user", content: "Explain quantum entanglement in one sentence." }
  ],
});

console.log(response.choices[0].message.content);
curl https://api.opsora.ai/v1/chat/completions \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer opsora-sk-xxxxx" \
  -d '{
    "model": "opsora-fast",
    "messages": [
      {"role": "user", "content": "Explain quantum entanglement in one sentence."}
    ]
  }'

// authentication

All API requests require a Bearer token in the Authorization header. Get your key from the dashboard.

Bearer Token

Include your API key in every request via the Authorization header. Do not embed it in query strings or request bodies.

Authorization: Bearer opsora-sk-xxxxx
example header 
Authorization: Bearer opsora-sk-xxxxx
Content-Type: application/json

Security Best Practices

  • → Never commit API keys to source control
  • → Use environment variables: OPSORA_API_KEY
  • → Rotate keys immediately if exposed
  • → Use separate keys for dev / staging / production

Rate Limits per Tier

Authentication also determines your rate limit tier. See rate limits for full details.

Tier Requests/min Tokens/min Burst
Free 10 5,000 20
Dev 60 50,000 120
Team 200 200,000 400
Enterprise unlimited unlimited unlimited

POST /v1/chat/completions Create a chat completion

Parameters

Name Type Required Description
model string required Model alias: opsora-fast, opsora-brain, opsora-code, opsora-vision, opsora-reason, opsora-max
messages array required Array of message objects with role and content
temperature number optional Sampling temperature (0–2). Default: 1.0
max_tokens integer optional Maximum tokens in the response. Default: model's max output
stream boolean optional Enable SSE streaming. Default: false

Model Selection Guide

opsora-fast — Chatbots, real-time apps, high-volume tasks. Lowest latency and cost.
opsora-brain — General-purpose tasks, summarization, Q&A. Balanced speed and quality.
opsora-code — Code generation, debugging, refactoring. Optimized for programming languages.
opsora-vision — Image analysis, OCR, visual Q&A. Accepts image URLs or base64.
opsora-reason — Math, logic, multi-step reasoning. Chain-of-thought by default.
opsora-max — Highest quality across all tasks. Use when accuracy matters most.

// error codes

All errors return a consistent JSON structure with type, message, and code fields.

error response format 
{
  "error": {
    "type": "error_type",
    "message": "Human-readable description.",
    "code": 400
  }
}
Code Type Description Suggestion
400 invalid_request_error The request body is malformed Check JSON format and required fields
401 authentication_error Invalid or missing API key Verify your Bearer token
429 rate_limit_error Too many requests Wait or upgrade your plan
502 upstream_error Backend model returned an error Retry — fallback will activate
503 model_unavailable Model is temporarily down Use a different model alias
504 timeout_error Upstream request timed out Reduce max_tokens or retry

Handling Errors

python — retry with backoff 
import time
from openai import OpenAI, APIError, RateLimitError

client = OpenAI(
    base_url="https://api.opsora.ai/v1",
    api_key="opsora-sk-xxxxx",
)

def chat_with_retry(messages, max_retries=3):
    for attempt in range(max_retries):
        try:
            return client.chat.completions.create(
                model="opsora-fast",
                messages=messages,
            )
        except RateLimitError:
            wait = 2 ** attempt
            print(f"Rate limited. Retrying in {wait}s...")
            time.sleep(wait)
        except APIError as e:
            print(f"API error: {e}")
            raise

python — chat completion 
from openai import OpenAI

client = OpenAI(
    base_url="https://api.opsora.ai/v1",
    api_key="opsora-sk-xxxxx",
)

# Standard completion
response = client.chat.completions.create(
    model="opsora-code",
    messages=[
        {"role": "system", "content": "You are an expert Python developer."},
        {"role": "user", "content": "Write a decorator that caches function results."}
    ],
    temperature=0.3,
)

print(response.choices[0].message.content)

# Streaming
stream = client.chat.completions.create(
    model="opsora-fast",
    messages=[{"role": "user", "content": "Tell me a story."}],
    stream=True,
)

for chunk in stream:
    if chunk.choices[0].delta.content:
        print(chunk.choices[0].delta.content, end="")

Go

go — chat completion 
package main

import (
    "context"
    "fmt"
    openai "github.com/sashabaranov/go-openai"
)

func main() {
    config := openai.DefaultConfig("opsora-sk-xxxxx")
    config.BaseURL = "https://api.opsora.ai/v1"

    client := openai.NewClientWithConfig(config)

    resp, err := client.CreateChatCompletion(
        context.Background(),
        openai.ChatCompletionRequest{
            Model: "opsora-fast",
            Messages: []openai.ChatCompletionMessage{
                {Role: openai.ChatMessageRoleUser, Content: "Hello!"},
            },
        },
    )
    if err != nil {
        panic(err)
    }

    fmt.Println(resp.Choices[0].Message.Content)
}

// rate limits

Rate limits are applied per API key. Upgrade your tier to increase limits. Burst allows short spikes above the sustained rate.

Tier Requests/min Tokens/min Burst
Free 10 5,000 20
Dev 60 50,000 120
Team 200 200,000 400
Enterprise unlimited unlimited unlimited

Rate Limit Headers

Every response includes rate limit information in the headers:

response headers 
X-RateLimit-Limit-Requests: 60
X-RateLimit-Remaining-Requests: 54
X-RateLimit-Reset-Requests: 2026-07-29T12:01:00Z
X-RateLimit-Limit-Tokens: 50000
X-RateLimit-Remaining-Tokens: 48231
X-RateLimit-Reset-Tokens: 2026-07-29T12:01:00Z

Exceeding Limits

When you exceed the rate limit, you'll receive a 429 response with a Retry-After header indicating how many seconds to wait. Implement exponential backoff for production workloads.
